# Bubble 剧情、事件与新手引导统一工作流

本文件统一“怎么接单、怎么路由、怎么交付”，具体字段含义由各领域原始规则负责。不要把三套系统的字段强行合并成一张表。

## 1. 输入源和选择条件

| 领域 | 活动需求池 | 有效输入 | 默认输出根目录 |
|---|---|---|---|
| 剧情 / 事件 | `策划/配置表/剧情、事件AI配置/剧情事件需求池.xlsx` 的 `填写需求` | 状态为“待配置”且 D 列“需求一句话”非空 | `策划/配置表/剧情、事件AI配置/AI生成/<功能_日期>/` |
| 新手引导 | `策划/配置表/新手引导AI配置/新手引导需求池.xlsx` 的 `填写需求` | 状态为“待配置”且两个必填字段完整 | `策划/配置表/新手引导AI配置/AI生成/<功能_日期>/` |

用户点名单行或功能名时只处理匹配项。未点名时按活动池中的序号或行号升序处理。不要扫描归档和历史输出来学习规则；稳定经验应来自当前规则文档、当前源表与代码。

剧情 / 事件旧目录 `剧情事件AI输入模板/` 仅保留已有链接和历史资料，不再接受新的日常需求。剧情 / 事件完整领域流程见 [剧情事件AI配置工作流](story-event/剧情事件AI配置工作流.md)。

## 2. 任务路由

| 需求信号 | 主路由 | 必要链路 |
|---|---|---|
| 纯过场、自动对白、Timeline、奖励或发任务 | 剧情 | `tPlot → tPlotStep → 对白/Timeline/奖励/任务` |
| 只改一组角色对白 | 对话 | `tDialogueTable → tDialogContent → tGuideTrole/tlanguage_cn`，并反查消费者 |
| 角色或对象出现，玩家点击/靠近后说话 | 事件内对话 | 事件详情 + `tEventGroup/Pool/Trigger` + 对话链 |
| 矿下 NPC、团餐、流行菜、特殊顾客、商人等 | 事件 | `Trigger → Pool → Group → 同 ID 详情表` |
| 教玩家完成操作、跨界面点击、输入锁和中断恢复 | 新手引导 | `tGuideGroup → tGuideLogic`，有对白时再接对话链 |
| 事件后播剧情、引导后启事件/剧情等 | 跨域链 | 先画出信号生产者和消费者，再按依赖拓扑生成 |

无法从一句话判断时，先输出分类依据和待确认项；可继续生成审查草案，但不能隐藏不确定性。

## 3. 跨域依赖

以下键容易混用，写表前必须单独列出：

```text
tEventTrigger.eventPoolId[] 元素 = tEventPool.eventType
tEventPool.eventTypeId[] 元素     = tEventGroup.groupId
tEventGroup.id                    = 对应事件详情表.id
tPlot 事件条件参数                = 具体 tEventGroup.id
```

跨域常见信号：

- 事件完成后播剧情：先形成可完成的具体 `tEventGroup.id`，再让 `tPlot.hangCondition` 的对应项为 `2`，参数为该具体 ID。
- 完成前一事件启动后一事件：后件 `tEventTrigger.eventTriggerType=6`，参数为前件具体 `tEventGroup.id`。
- 完成引导启动事件：`tEventTrigger.eventTriggerType=8`，参数为引导 ID。
- 完成引导启动剧情：`tPlot.hangCondition` 使用引导条件类型 `4`，参数为引导 ID。
- 新手引导中的场景对话：引导步骤引用对白组；必须验证对白组、单句、角色和语言链。

同一需求跨多个系统时，推荐生成顺序为：

1. 语言、角色、条件、奖励等叶子依赖。
2. 对话单句与对白组。
3. 事件详情和具体事件 `tEventGroup.id`。
4. 事件 Pool 与 Trigger，或引导 Logic 与 Group。
5. 剧情步骤与剧情入口。
6. 反向验证信号生产者能实际完成、消费者能收到正确 ID。

顺序可按真实依赖调整；例如“引导完成后启动事件”应先确定引导 ID，再配置事件触发器。

## 4. 状态与并发

每条活动需求遵循：

```text
待配置 → 配置中 → 已完成
              └→ 待配置 + 需要确认原因
```

- 开始处理后再把目标行改为“配置中”，避免多人重复处理。
- “已完成”只表示草案、回读与约定 QA 已完成，不等于正式区已激活。
- 用户中途取消、文件被占用或高风险字段无法闭合时，不留下假完成状态。
- 工作簿存在 Excel 临时锁文件时先确认占用；不要覆盖正在被成员编辑的活动池或输出文件。

## 5. 证据和假设

每个关键值标记来源：

- `S`：用户或正式策划需求明确给出。
- `T`：当前表、代码、Prefab、枚举或关联数据直接证明。
- `D`：由 S/T 可复核推导。
- `A`：为了形成可审查草案而补的假设。

高风险字段必须优先取得 T 证据：触发类型及参数、Event/Guide/View ID、Prefab 节点路径、点击回调、`SystemEntry`、Timeline/特效资源、存档与中断策略、输入锁、奖励与外键。无法验证时保留为 `A-假设` 并给出实机测试步骤。

## 6. 工作簿写入

1. 复制目标 Sheet 所属的完整源工作簿到本次输出目录。
2. 分别在每张目标 Sheet 的 A 列定位首个严格等于 `END` 的行；记录行号。
3. 新增行从 `END+1` 开始；修改行完整复制到草案区后再改。
4. 样式和公式从同类成熟行继承，不从相邻但不同类型的行盲抄。
5. A 列写明 `[AI草案][新增/修改][S/T/D/A] 用途`。
6. 保持 `END` 原位，草案默认不导出。只有明确授权后才执行激活流程。

需要公式拼接 ID 列表时，必须在兼容引擎重算并保存；交付前既检查公式文本，也检查缓存结果是否可读。

## 7. 领域执行摘要

### 剧情

先确认自动触发还是程序直接启动，再按语言 → 角色 → 单句 → 对白组 → Timeline/奖励/任务 → `tPlotStep` → `tPlot` → 外部入口生成。禁止使用未实现的 `stepType=3`；不要把 `stepType=5` 当通用开界面；`tDialogContent.roleId` 指向 `tGuideTrole`。

### 事件

先判定 `eventType` 和同 ID 详情表，再配置 `tEventGroup`、`tEventPool`、`tEventTrigger`。四类 ID 分开记录。事件内对白与事件完成后的剧情对白应明确分工，避免重复播放。经营烹饪 `tManageEvent*` 是独立链，不接核心事件池。

### 新手引导

先给出候选入口、`keepEvent`、事件参数、附加门槛、玩家动作骨架和真实验证方式；再配 `tGuideLogic`，最后配 `tGuideGroup.guides/nextId`。用户允许沿用的是动作骨架，不是旧行所有字段。对 `withoutSaving`、`breakRestartType`、`lockOnFinish` 必须解释选择理由并设计中断测试。

## 8. QA 矩阵

### 所有领域

- 重新打开最终文件；核对文件真实位于请求的输出目录。
- 检查 6 行协议头、Sheet 名、字段顺序、类型、样式、隐藏状态、图片、数据验证和 `END` 位置。
- 检查正式区与草案区合并后的 ID 唯一性、号段、父子前缀和 Int32 范围。
- 解析全部新增/修改的 `arr` 与复合 JSON；扫描 `#REF!/#DIV/0!/#VALUE!/#NAME?/#N/A`，区分导出字段与历史辅助列。
- 检查语言正文非空、富文本标签和占位符数量一致。
- 渲染所有受影响 Sheet，确认长文本、草案行、表头和关键字段可读。

### 剧情 / 对话

- `tPlot.plotStep[]`、步骤参数、对白组、单句、角色、语言、Timeline、奖励和任务引用闭合。
- 自动剧情有有效条件且参数一一对应；场景与触发时机一致。
- 对白暂停、跳过和奖励节点按当前代码行为核对。

### 事件

- Trigger 的池标签/权重长度一致；池标签可达。
- Pool 的 groupId/权重或次数长度一致，区间无非预期遮挡。
- 每个具体 Event ID 在正确详情表存在，完成方式能发出具体 ID。
- 后续事件或剧情消费具体 `tEventGroup.id`，不消费其他三类 ID。

### 新手引导

- 触发链能从真实代码/条件闭合到第一组；手动 Alt+0 不能替代真实触发验证。
- 组链、逻辑、对话、语言和角色引用存在；每个点击路径能到真实回调和目标系统。
- 存档、中断、跨界面接链和输入锁至少有新存档与中断重进测试设计。
- 文案执行状态、角色知识、话题连续性和行动可执行性检查。

## 9. 交付与成熟度

每次交付至少包含：

- 修改后的完整工作簿副本；
- `generation-manifest.json`：请求、输出目录、源/目标工作簿、Sheet、ID、动作和来源；
- 配置记录：分类、触发链、S/T/D/A、ID 台账、引用图、变更摘要、待确认项；
- 回读、公式、JSON、外键和视觉 QA；
- 可复现的真实触发、中断重进与游戏内验证步骤。

使用以下成熟度之一，不混用：

- `草案已生成，静态 QA 通过，尚未导出`。
- `草案已激活并导表，待客户端实机验证`。
- `客户端实机验证通过`。
- `阻塞：<具体原因>`。

## 10. 活动池归档

- 剧情 / 事件活动池中“已完成”记录达到 50 条时，先追加到 `策划/配置表/剧情、事件AI配置/AI生成/配置记录/YYYY-MM.xlsx`。
- 新手引导按其领域工作流规定的归档位置处理。
- 归档工作簿回读成功后，才从活动池移出旧记录；归档不替代规则文档和当前项目证据。
