# Bubble 新手引导 AI 配置工作流

> 版本：1.0（2026-09-02）  
> 适用对象：策划、客户端、测试，以及需要让 AI 配置新手引导的团队成员。  
> 配套规范：[新手引导配置说明_给AI使用.md](新手引导配置说明_给AI使用.md)

## 1. 这套工作流解决什么问题

团队成员不需要记住 `tGuideGroup`、`tGuideLogic` 的全部字段，也不需要每次复制一份需求表。只要把需求追加到固定需求池，AI会根据本工作流和配置说明完成：

```text
需求池待配置行
    ↓
读取规范、现有链路、代码、Prefab和关联表
    ↓
先定真实触发，再配逻辑步骤，再挂引导组
    ↓
在输出副本的合适位置生成草案
    ↓
回读、静态QA、逻辑/文案扫描、渲染检查
    ↓
需求池改为已完成 + 输出配置记录
    ↓
策划确认后，人工/授权激活到正式区
```

核心原则：**需求描述决定“玩家要经历什么”，代码和表结构决定“具体字段怎么写”。**

## 2. 团队文件分工

| 文件/目录 | 谁维护 | 用途 | AI日常是否读取 |
|---|---|---|---|
| `新手引导需求池.xlsx` | 全体策划 | 唯一活动需求入口；只处理状态为“待配置”的行 | 是，只读待配置行 |
| `新手引导配置说明_给AI使用.md` | 配置负责人 | 完整字段、触发、存档、中断、错误复盘和文案规则 | 是，每次任务先读 |
| `新手引导AI配置工作流.md` | 配置负责人 | 团队执行流程、角色分工、交付门槛和固定指令 | 是，每次任务先读 |
| `新手引导需求填写模板.xlsx` | 配置负责人 | 新项目/新成员需要时复制的空白需求池 | 仅复制时使用 |
| `AI生成/二楼引导_日期/` | AI + 配置负责人 | 每次生成的配置表、清单、QA和预览 | 只读本次结果 |
| `AI生成/配置记录/YYYY-MM.xlsx` | AI自动归档 | 已完成需求历史记录 | 默认不读；需要追溯时按需读 |

历史需求不是经验库。新的通用经验必须回写到主说明文档和需求池的“AI配置规则”页，而不是要求 AI 每次扫描全部历史记录。

## 3. 角色分工

### 3.1 需求提交人

只需在需求池末尾新增一行：

- 填写“功能/界面”和“希望玩家学会什么”两个必填字段。
- 触发、步骤、界面 ID、控件路径、存档方式等都可以不填。
- 状态保持“待配置”。
- 如果有明确限制，再补一句“补充要求”，例如“必须第一次打开时触发”“不要出现具体材料名称”。

### 3.2 AI执行人

收到固定指令后，AI负责：

1. 只读取状态为“待配置”且两个必填字段完整的行。
2. 先把目标行改成“配置中”。
3. 读取本工作流、主说明、目标源表、相关代码/Prefab和关联表。
4. 只在输出副本中生成草案，不强制放在 `END` 下方，也不直接改正式源表或其他正式文件。
5. 回读并执行静态 QA、逻辑/文案 QA、视觉检查。
6. 成功后把状态改为“已完成”，回填生成表、ID、文件位置、假设、待确认项和完成时间。
7. 失败或无法安全判断时恢复“待配置”，在“需要确认”列写清原因。

### 3.3 策划确认人

重点确认：

- 玩家动作顺序和真实触发时机。
- AI标记为 `A-假设` 的 ID、路径、数值、文案和行为。
- 文案是否符合角色性格和项目整体风格。
- 是否批准把草案交给人工/项目发布流程处理；AI 不直接写正式区。

### 3.4 客户端/测试

重点验证：

- 代码事件、界面 ID、Prefab 节点和点击回调是否与草案一致。
- 新存档、真实事件触发、中断重进、跨界面接链和输入锁。
- 通过项目导表器后，客户端实际加载的表和 BSON 是否更新。

## 4. 成员日常操作

### 4.1 提交需求

打开 `新手引导需求池.xlsx` 的“填写需求”页，在表格末尾新增一行，只填：

```text
功能/界面：玩家要学哪个功能
希望玩家学会什么：玩家最后要能做什么
状态：待配置
```

其余内容不确定可以留空。不要复制新表，不要修改历史已完成行。

### 4.2 启动 AI

把下面一句话原样发给 AI：

> 处理需求池里待配置的内容。

如果只想处理某一行，可以补充功能名，但不能要求 AI 跳过规范和 QA：

> 处理需求池里“二楼引导”这一行，按新手引导 AI 配置工作流执行。

### 4.3 审核 AI 结果

先看需求池“需要确认”列，再看本次输出目录中的：

1. `二楼引导_配置记录.md`：理解触发链、假设和文案决策。
2. `generation-manifest.json`：核对工作簿、ID和输出归属。
3. 预览图：确认副本中的草案位置、文本和样式。
4. 四份配置表：确认只生成了输出副本，正式源文件没有被修改。

没有明确说“激活/写入正式区”前，草案不视为游戏已生效。

## 5. AI固定执行流程

### 阶段A：接单和状态锁定

- 只读待配置行；不从历史归档学习规则。
- 处理前写“配置中”，避免多人重复处理。
- 必填信息缺失时，可以根据上下文先补一版，但必须标记 `A-假设`。

### 阶段B：建立证据包

按优先级取证：

1. 用户明确需求（S）。
2. 当前源表表头、相邻成熟链和已有 ID（T）。
3. C# 运行时代码、`eVIEW_ID`、`SystemEntry`、Prefab 层级、点击回调（T/S）。
4. 从上述事实推导的值（D）。
5. 仍无法确认的测试值（A-假设）。

高风险字段必须有代码或关联表证据，不能只凭截图、节点名字或旧行位置判断：

- `keepEvent` 与参数槽 `viewId/roomId/formBuilding/keepUINode`。
- `funcType`、`uiComPath`、目标节点和最终打开的系统。
- `viewId` 与 `guideViewId` 的各自职责。
- `withoutSaving`、`breakRestartType`、`lockOnFinish`。
- `hideModule`、镜头参数、特效资源和语言 ID。

### 阶段C：先定触发，再拆步骤

AI必须先写出下面的触发结论，才能开始填表：

```text
候选入口：formLevel / 前组nextId / 条件或事件 / 界面事件
启动事件：keepEvent及中文含义
事件参数：viewId、roomId、formBuilding、keepUINode等
附加门槛：conditionViewId、delay、Ready/Active
玩家动作骨架：按原需求保留哪些步骤，顺序是什么
真实验证：玩家做什么操作可以触发
```

注意：**用户说“步骤可以沿用”时，沿用的是玩家动作骨架，不是旧行所有字段。**

### 阶段D：配置逻辑和组

按以下顺序：

1. 复制目标正式工作簿到输出目录，并确认源文件保持只读。
2. 根据目标 Sheet schema 在副本中选择可追踪的草案位置；不强制放在 `END` 下方。
3. 在副本中为 `tGuideLogic` 和 `tGuideGroup` 写入步骤、触发、链路、存档和中断字段；若存在 `END`，保留其位置和导出语义。
4. 将逻辑 ID按执行顺序写入 `guides`。
5. 如果使用 `nextId + keepEvent=9`，确认下一组一定由前组推进，不把 `keepEvent=9` 当独立入口。
6. 所有数组写严格 JSON；保留字段拼写如 `uiClikCondition`、`offect`、`BehaviorSyetem`。

### 阶段E：按经验规则填默认值

#### 存档

```text
能安全保存本组结束状态？
├─ 能：withoutSaving=0
└─ 不能，必须整段完成
   ├─ 链中：withoutSaving=2
   └─ 链尾：withoutSaving=1
```

跨界面、不可拆分的连续教学一般使用 `2/2/.../1`。注意异常中断不一定自动恢复存档，值为1的组必须是稳定、短小、能高概率完成的链尾。

#### 中断

- `breakRestartType=0`：关键教学和必须真正完成的链的默认值，从触发链重新开始。
- `breakRestartType=1`：代码支持续跑，但当前正式表无成熟样例，不自动使用。
- `breakRestartType=2`：可跳过的介绍或动画；带关键后续时必须专项设计 `addGuideOnBreak`，不能直接套用。

如果为了跨界面链设置非零 `reGuideIdOnBreak`，必须标 `A-假设`，并在报告中写明“正式表无成熟样例，需实机中断测试”。

#### 输入锁

- `lockOnFinish=true`：只有下一组已存在、会立即且确定接管输入时使用。
- `false`：链尾、等待外部界面事件、动态气泡、目标可能失效时使用。
- 设置为 true 后必须检查 `nextId`、下一组触发、`guides` 和所有逻辑 ID。

#### 常见步骤

| 需求 | 优先配置 | 必查 |
|---|---|---|
| 点击普通 UI 按钮 | `funcType=0`、真实 `guideViewId + uiComPath` | EventAdaptor、`uiClikCondition=0`、路径回调 |
| 点击运行时气泡 | `funcType=8`、真实气泡子节点名；需要提示时加 `effectIdArray` 手指特效 | BubbleManager 查找根、`effectPosType/Array` 与 `followTarget`、节点唯一性、点击后打开的系统；不能套普通 UI 的 `funcType=0` |
| 打开界面后继续 | `keepEvent=0`、`viewId=目标界面` | `viewId>0`、事件 ViewId相等；`guideViewId`不能代替它 |
| 移动镜头 | `funcType=11` | `[x,y]`、size、毫秒时间；不要虚构Z |
| 场景对话 | `funcType=4`、`dialogueGroupId` | 对话组→内容→语言→角色完整引用链 |

### 阶段F：文案生成

先做四行简报：

```text
当前界面/事件状态：已经发生什么，尚未发生什么
角色知道什么：信息来自事件、界面还是前一句
本场已提及话题：后句只能回应这些话题
玩家下一步：对话结束后实际能做什么
```

默认对话节奏：

1. 奶茶鼠给状态锚点和情绪。
2. 奶茶鼠用可爱、轻快的方式说明小麻烦。
3. 阿白用温和、简短、可执行的话收束。

项目文风要求：整体可爱俏皮；`nia` 是偶尔的口癖点缀，不是把直白句硬改可爱的工具；去掉 `nia` 后句子仍要自然。未提供具体材料、道具或数量时，只能说“几样材料”“界面里的材料需求”等受控泛称，不能自行创造清单、下午茶或角色手持物。

### 阶段G：QA和交付

必须完成以下检查：

- ID表内唯一，新增 ID符合目标表号段并记录台账。
- 组链、逻辑 ID、对话组、内容 ID、语言 ID和角色 ID全部存在。
- 触发结论能从真实代码/条件表闭合到第一组。
- 正式源文件保持不变；副本中的草案位置和（如存在）`END` 导出语义可回读。
- 所有 `arr` 是严格 JSON，字段类型和 0/空语义正确。
- 执行 logic-guard：角色知识、物理状态、话题触发、行动可执行、修改联动。
- 渲染受影响 Sheet，确认表头、草案行、长文本和颜色可读。
- 明确标注“静态可用/待实机确认”，没有运行验证不能写成正式生效。

成功交付后，需求池必须回填：

- 生成了哪些配置表。
- 使用了哪些新增、复用、修改 ID。
- 输出文件位置。
- AI自行补充了哪些 `A-假设`。
- 是否需要策划/程序确认。
- 完成时间。

## 6. 激活、归档和版本管理

### 6.1 激活正式配置

只有策划明确授权“激活/写入正式区”后，才可由人工/项目发布流程处理：

1. 复核草案和待确认项已关闭。
2. 将审核通过的草案交给人工发布流程，由负责人决定如何合并到正式区。
3. 发布前保证同一 ID 的冲突已解决，并保留原始副本和回滚版本。
4. 由负责人运行正式导表器并核对 BSON/客户端产物。
5. 在配置记录中写明激活时间、负责人和导表版本；AI 不直接执行这些正式文件写入。

### 6.2 需求池归档

活动需求池只保留待配置、配置中和最近20条已完成记录。超过20条时：

1. 按完成时间追加到 `AI生成/配置记录/YYYY-MM.xlsx`。
2. 回读归档文件确认成功。
3. 再从活动池清理已归档行。

归档记录不是经验库；经验必须先提炼回主说明和规则页。

修改工作流或通用规则时，在本文末尾追加变更记录：

## 7. 团队交付门槛

一份 AI 新手引导配置只有同时满足以下条件，才算“可交接”：

- 有完整触发结论，不只是步骤表。
- 逻辑步骤、组链和所有外键可回读。
- 用户保留的步骤没有被擅自删除或改序。
- 高风险字段有代码/Prefab/关联表来源，假设已单独列出。
- 文案通过项目文风和 logic-guard 检查。
- 输出文件、ID、假设、确认项和 QA 结果齐全。
- 明确区分“草案生成成功”和“已经导表生效”。

遇到无法确认的高风险路径、枚举、真实触发或存档行为时，AI应先生成可审查草案并标记待确认，不得假装已经验证。
